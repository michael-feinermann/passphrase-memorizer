# Internal security audit

Review updated: 7 October 2026. Product: Passphrase Memorizer 1.0.0, build 1, independent from Password Generator.

## Scope and conclusion

This internal review covers the native model worker, Swift process protocol, input validation, volatile session lifecycle, permitted preferences, screen exposure, dependency pinning and release packaging. Source review and executed tests establish the controls below. The AI worker's network and filesystem-write restrictions are enforced by the tested macOS kernel policy, and the application implements no persisted input, result or conversation history. The final lifecycle review identified a shutdown gap in the earlier build: a delayed kill timer could disappear when the GUI exited, including a worker cancelled shortly before quitting. The rebuilt source closes launches, retains/reaps active and cancelling workers, owns pending prompts before task scheduling, and waits for late-response cleanup before replying to orderly quit. It also synchronously overwrites mounted input text storage. These corrections passed independent source review and the rebuilt Debug, Release and isolated Release AddressSanitizer suites, each with 29 tests and no failures or skips. This is not a third-party audit, formal proof or certification of macOS. Password Generator and its cryptographic construction remain unchanged.

The rebuilt app passed native GUI checks, Apple notarization and the default signed app/ZIP release verifier on 7 October. The final exported helper also passed a public Gemma inference check. Publication, verified public download and installed-app verification remain separate open gates at this snapshot; the notarized local export does not by itself establish a completed public release.

## Security boundaries

The GUI accepts an existing word sequence and a manually selected local GGUF. It creates a fresh native worker for each generation. Only the worker links llama.cpp, and it has no HTTP server, remote model client, tools, browser or connection to another AI application. Its native macOS Seatbelt policy is established before sensitive input is read. Mandatory denial probes must pass before its `MSAI` handshake. The GUI then checks the identity and Hardened Runtime status of the actual running child through macOS Security's PID-based guest-code API before writing even the prompt length. The child must still be running and the request active; failed attestation blocks all prompt bytes. The worker exits after generation. Input and result remain volatile session state.

The GUI requires Hardened Runtime, the expected signing team and the expected main/runner identifiers, with no capability-bearing entitlements or runtime exceptions. It has no networking implementation. This is distinct from the worker's kernel-enforced network prohibition: the GUI itself is not a process with a kernel network-denial policy. App-managed preferences intentionally write only `preferredLanguage`, `windowWidth` and `windowHeight`. A three-key allowlist removes framework-created navigation bookmarks (`NSNav*` and `NSOSP*`) and window autosave keys from the app domain at startup, after the dialog closes and during orderly shutdown. It preserves other applications' domains and cannot revoke global Finder or other operating-system metadata. The GUI is not an App Sandbox process because the custom worker sandbox must be established in a new process and cannot be nested under an inherited App Sandbox.

The local model file and runtime are intentionally installed software, not session data. No prompt, result, transcript, selected model path or security-scoped bookmark is intentionally written. The model is loaded for inference and is not trained or modified using input. The selected model must be a regular local file. Symlinks, dataless placeholders, mounted network filesystems and known cloud-provider paths are refused in both the GUI and worker. System libraries, the exact selected model, self process information and read-only system queries are the worker's permitted reads. GPU mode additionally permits metadata of the actual executable's direct parent directory, under both its canonical path and the verified dyld spelling, plus metadata of the public `/var` or `/tmp` alias only when that actual launch requires it. It does not permit listing the directories or reading their files. The paths come from `_NSGetExecutablePath` plus successful `realpath`, not caller-controlled `argv[0]`. Unrelated home-directory or configuration-file access is denied.

## Native acceleration boundary

The statically linked Metal backend is selected only after it computes and reads back a fixed public eight-float addition successfully. Denial probes run again before `MSAI`. The automatic path falls back to the CPU on graceful unavailable/failed preparation; fatal driver faults and later inference failures abort the request. This is capability selection, not measured CPU/GPU calibration for every request. Forced `--cpu` and `--metal` modes allow public-fixture verification without saving a backend preference.

The GPU profile adds exactly the `AGXDeviceUserClient`, a lookup for Apple's `com.apple.MTLCompilerService`, and narrowly specified metadata literals. These cover the actual direct executable-parent directory in canonical and dyld spelling, and the public `/var` or `/tmp` alias itself only if the actual dyld path begins with `/var/` or `/tmp/` and its verified canonical path begins with the corresponding `/private/var/` or `/private/tmp/`. No additional file content, directory listing, filesystem write or network permission is granted. An independent public empty-command-buffer diagnosis isolated the directory-metadata requirement: without it CoreFoundation Metal telemetry crashed before readiness. A packaged launch through `/var` exposed the additional alias metadata requirement; no `Info.plist` contents are read. Final packaged-helper alias verification passed with actual GPU computation and both canonical/dyld directory listings denied. A forged `argv[0]` did not change policy permissions. Broad IOKit properties and other Mach services were not required and were removed.

The pinned dependency checkout remains unchanged. Reviewed, drift-checked build overlays embed build-time compiled default/tensor shader libraries and the Half/Bfloat capability probes, remove the shader-source compiler, refuse file-based shader fallback and remove automatic Metal registry initialization from the CPU path. Metal is registered explicitly after the public GPU preparation succeeds. Its fixed shader IR and scalar specialization constants go to the Apple compiler; prompt strings and tensor contents do not. Constants in the pinned backend include tensor shapes and workload dimensions, so they must not be described as wholly fixed or free of session-related metadata. Apple's compiler runs under its own OS policy, which allows shader caches and logs outside the worker's filesystem-write denial. GPU mode therefore expands the trusted components to Apple's compiler and GPU driver; derived workload metadata may remain outside the worker. This OS-service boundary is part of the remaining trust assumption.

This build has no Core ML/Apple Neural Engine backend. M5 GPU Neural Accelerators are distinct from the separate Neural Engine; GPU tensor support is conditional on hardware and OS compatibility. Normal cleanup synchronizes pending GPU work before and after clearing the model memory cache. The backend clears shared buffers using a CPU write and private buffers using a GPU fill followed by completion waiting. This is a normal-cleanup attempt, not a guarantee about every activation, allocator pool, driver copy or physical GPU cache. The reviewed Metal overlay also exposes the pinned backend's existing abort-callback setter through the generic registration name used by `llama_context`. Cancellation is cooperative at model-loading, llama/worker control points and backend-supported boundaries; already submitted Metal command buffers are not guaranteed to be preempted. The parent's two-second forced-kill escalation and reap barrier remain necessary.

## Secret lifetime

Swift session storage uses exclusive page-aligned `mmap` allocations. `clear()` overwrites the complete allocation with `memset_s` and invalidates all reference aliases. Page locking is attempted. UI and parsing still create Swift/AppKit copies outside that owned-buffer guarantee. The input view disables undo and synchronously overwrites its mounted live text storage during Clear and orderly quit, with another clear during view dismantling; it never adds plaintext to SwiftUI state.

The worker requires successful locking of its explicit prompt, formatted prompt, token, grammar, result and temporary token-piece buffers before reading the prompt. Owned native buffers use explicit volatile overwrite on normal destruction and handled cancellation. Plain prompt/formatted buffers are cleared after tokenization; grammar text is cleared after the constrained sampler is initialized. On normal cleanup the llama memory cache is cleared and the sampler reset before destruction. Every generation ends its worker process. `mlockall` for third-party allocations is attempted but may fail. A stuck worker is forcibly killed after the grace period; forced termination does not run native destructors.

Story rendering preserves literal square brackets and styles each complete `[word]` range blue and bold using plain attributed text. It does not parse output as HTML or executable markup. Revealing starts a ten-minute timer; app deactivation, explicit concealment and session clearing conceal it sooner. The longer display interval increases visual exposure, so deactivation protection and reveal confirmation remain enabled. Attributed-string and text-rendering copies remain outside the owned-buffer wipe guarantee.

There is no multi-turn model memory or persisted transcript. Clearing removes the current application session, invalidates pending results and cancels the worker. Closing the last window and orderly quitting invoke the same cleanup. Orderly quit permanently closes the worker launch gate and keeps the GUI alive until all active/cancelling children are reaped and response tasks have wiped late results. Pending request prompts are owned before task scheduling and are cleared synchronously on cancellation. The remaining model selection and filename are volatile setup state and are discarded on termination. Window size and language are the intentionally retained app settings.

## Compatibility and remaining limits

The macOS SDK declares `sandbox_init` deprecated and no longer supported; custom Seatbelt profile semantics are not a stable public API. Activation or failed probes block generation. Successful probes establish the tested restrictions on the tested macOS version, not permanent compatibility with future systems. Apple recommends App Sandbox for supported app sandboxing; its container-write permissions and inheritance behavior differ from this worker's required write-denial model.

Hardened Runtime reduces code injection and debugging opportunities, but does not authenticate a model publisher, prevent malicious administrator/kernel code or guarantee erasure. Core dumps are disabled in GUI and worker. Worker termination removes its active address space, while registers, allocator remnants, Swift value copies, UI buffers, llama.cpp activation/KV-cache/compiled-grammar allocations, Metal private/shared resources, GPU/driver caches, Apple compiler caches/logs, compressed memory, swap, crash reporting and snapshots cannot all be located and overwritten reliably. Memory locking reduces paging of controlled buffers; it is not an all-process guarantee. Forced quit, `SIGKILL`, a crash or power loss may prevent cleanup hooks.

Screen capture prevention is best effort. A captured story can reveal the phrase. The app cannot revoke screenshots, external camera recordings, text copied/retyped elsewhere, clipboard-manager copies made before input, global OS metadata or copies on a compromised host. No irrevocable physical-memory or external-copy deletion guarantee is made.

Host integrity remains a prerequisite. The helper has both a prelaunch signature check and a running-child identity check before prompt delivery. Model size/mtime checks are not an authentication proof against a malicious same-user writer; obtain and verify a model from a separately trusted publisher before using it. Model weights are native-parser data from a separately trusted publisher. The fixed llama.cpp revision reduces build drift; it is not proof that the parser and engine contain no vulnerabilities. Source-to-binary reproducibility, third-party penetration testing and formal verification are outside this internal review. Code signatures and notarization establish distribution identity and Apple's acceptance checks, not absence of implementation flaws.

Input validation checks wordlist membership for 1 through 128 words, preserving capitalization and order. It does not validate wallet seeds or BIP39 checksums. BIP39 defines lengths of 12, 15, 18, 21 and 24 words with a checksum; other lengths are generic word sequences. EFF membership does not prove random selection. Whitespace and EFF hyphens delimit words, so the original password's complete formatting remains authoritative. A story changes neither the password nor its entropy.

Auch noch nicht gestartete Prompts und der gemountete Eingabespeicher werden direkt geleert. Diese Korrekturen bestanden die unabhängige Quellcodeprüfung und die neuen Suiten mit jeweils 29 Tests in Debug, Release und mit isoliertem AddressSanitizer, ohne Fehler oder ausgelassene Fälle. Enthalten sind ein SIGTERM ignorierender Prozess nach dem Leeren, gesperrte spätere Starts, direkt geleerte noch nicht gestartete Prompts, das Warten auf die Löschung verspäteter Ergebnisse und das synchrone Leeren des Eingabespeichers ohne SwiftUI-Aktualisierung. Auch die blauen und fetten vollständigen Wortmarker sowie unverändert dargestellter Text ohne Link- oder Markdown-Auswertung werden geprüft. Der KI-Prozess prüft die Sperren vor seinem Bereitschaftssignal; danach attestiert die Oberfläche den tatsächlich gestarteten Prozess und übermittelt erst dann den Prompt. Es gibt keinen gespeicherten Eingabe-, Ausgabe- oder Chatverlauf. Die eigenen App-Einstellungen speichern nur Sprache und Fenstergröße.

Die im Audit gefundenen Lücken bei defekten Pipes, übergroßen Eingabeersetzungen, Abbruch, System-Schreibwerkzeugen und unsicheren ZIP-Metadaten wurden behoben. Leeren, Schließen und reguläres Beenden entfernen die Sitzung, verwerfen verspätete Ergebnisse und bereinigen kontrollierte Puffer. Eine Ausgabegrammatik erzwingt die markierten Wörter einschließlich Großschreibung, Reihenfolge und Wiederholungen; die Oberfläche prüft sie erneut.

Die neue signierte Kandidaten-App und ihr ZIP bestanden am 7. Oktober die Paketprüfung mit echten CPU-/GPU-Berechnungen und den erforderlichen Sperrprüfungen. Die native Oberfläche zeigte Name und Version, den Dialog mit zehn Minuten, eine öffentliche Gemma-Merkhilfe mit korrekten wiederholten Wortmarkern sowie eine leere Sitzung nach dem Leeren. Reguläres Beenden während einer gestarteten 128-Wort-Generierung hinterließ keinen App- oder KI-Prozess. Blaue und fette Marker sind durch Attributtests belegt; die Screenshot-Sperre verhindert eine Pixelprüfung. Die neue Xcode-Notarisierung mit der Kennung `1BDDA6DE-FDD8-4BF8-8364-A6CEACB604FF` und die abschließende Standard-Paketprüfung bestanden. Das exportierte Bundle wurde danach nicht neu signiert; ausführbare Dateien und Ressourcen entsprechen dem geprüften Kandidaten. Eine weitere Gemma-GPU-Inferenz im endgültigen Export bestand ebenfalls. Nach dem regulären Beenden blieben genau die drei erlaubten Einstellungswerte erhalten. Veröffentlichung, verifizierter öffentlicher Download und Prüfung der installierten App sind in diesem Stand noch offen. Die eigene Seatbelt-Sandbox verwendet eine veraltete API und muss auf dem jeweiligen macOS funktionieren; andernfalls wird die Generierung gesperrt. Vollständige unwiderrufliche Löschung aller physischen Speicher-, Framework- und Betriebssystemkopien kann die App nicht garantieren. Der Audit ersetzt kein unabhängiges Gutachten oder formalen Sicherheitsbeweis.
